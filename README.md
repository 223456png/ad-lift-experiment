# 广告投放的增量效应分析

Criteo 公开的 uplift 数据集，1,398 万个用户，随机分成投放组（85%）和抑制组（15%）。

我从头跑了一遍：数据校验、主效应、依从性归因、分层、CATE、收益测算、稳定性，代码和图表都在仓库里。分析做完又补了一份设计推演，回答「如果重来一次，这个实验该怎么设计」。

## 结论

广告有增量。转化率 0.194% → 0.309%，相对提升 59.4%，p 值小到可以忽略；访问率 3.82% → 4.85%，涨了 27.1%。

这个 59.4% 不能直接对外讲。Criteo 在数据集说明里写过，他们做过非均匀子采样，原始增量水平没法从数据还原，能站住的只有方向。另外我自己查出来一件事：子采样还让分组和特征变得不独立（按 f0 分箱做 SRM，各箱的投放份额偏离 85%，z 值最大到过 +33），粗 ITT 里含向上混杂。

按 f0 分层加权是 +56.4%，按 CATE 十分位等权是 +48.7%。两个调整值差 8 个点，说明 f0 一个变量没把失衡吃干净，混杂的真实量级在 5%~18% 之间，不是一个数。对外我一般报 +56.4%，把 +48.7% 当下界。

比效应量更值得说的是：**96.4% 的投放对象根本没看到广告**。

还有个反常识的地方。分到投放组、但没拿到曝光的那批人，访问率 3.49%，比对照组的 3.82% 还低。同样没看到广告，被分到投放组的人表现更差。这不是投放让人变差，是曝光分配本身带着选择：系统倾向把曝光给更可能响应的人。所以拿曝光组直接和对照组比会严重高估：转化率差 5.18pp，真实的 ITT 只有 0.115pp，差 45 倍。

## 数据

Criteo AI Lab 的 AdKDD'18 数据集，CC BY-NC-SA 4.0，1,398 万行、16 列。`f0`–`f11` 是匿名化特征，`treatment` 是随机分组，`visit` 和 `conversion` 是两个结果标签。`exposure` 是「该用户是否至少被曝光过一次」的用户级 0/1 标志，不是曝光次数。这一点决定了后面所有口径，收益最多只能算到「每曝光用户成本」这一层。

分组是 15% 对照、85% 投放。不是 50:50，所以做 SRM 要按 85:15 检验，按 50:50 会误判成分流失败。

数据不进仓库，297 MB 超了 GitHub 单文件限制。克隆后先跑：

```bash
mkdir -p data
curl -L -o data/criteo-uplift-v2.1.csv.gz \
  "https://hf-mirror.com/datasets/criteo/criteo-uplift/resolve/main/criteo-research-uplift-v2.1.csv.gz"
gzip -t data/criteo-uplift-v2.1.csv.gz
```

hf-mirror 是国内镜像，实测 7.9 MB/s，半分钟下完。

## 先看数据能不能用

总量层面的 SRM 卡方约等于 0，p=0.999，分流和设计完全吻合。

协变量看了 12 个特征，最大标准化均值差 0.0488，按 0.1 的实务阈值算通过（严格说这不叫 AA 检验，AA 是把同一群人随机拆两半比指标，这里比的是两组协变量分布）。但在 1,398 万样本下，0.0488 对应 z≈65，统计上极显著，不是噪声。顺着这条线查下去，发现了更硬的问题。

按 f0 分箱逐箱检验投放份额：84.57% / 85.71% / 85.01% / 84.88% / 84.83%，对设计值 85% 的 z 值是 −20.3 / +33.2 / +0.7 / −5.6 / −7.9，联合卡方 1,607（df=4）。标准随机化下这基本不可能发生。解释只有一个：公开数据做过非均匀子采样，分组和特征不独立。后果很实在：高转化箱被过度分进投放组，粗 ITT 被向上混杂，按 f0 加权调整后是 +0.109pp。

标签也查了：`conversion=1` 而 `visit=0` 的行是 0，对照组出现 `exposure=1` 的行也是 0。数据本身没有逻辑错误。

## 投放了，但 96.4% 的人没看到广告

`P(exposure | treatment) = 3.60%`。1,188 万投放用户里，只有 42.8 万真的被曝光过。

把投放组按是否曝光拆开，三组放一起看：

![依从性](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/01_compliance.png)

没看到广告的两组，访问率差 8.7%（3.82% vs 3.49%），转化率差得更多（0.194% vs 0.119%，低 38%）。同样的「没看到广告」，被分到投放组的反而更差，说明曝光不是随机发的。

这一条直接排除了「曝光组 vs 对照组」的比法。那样算出来转化率差 5.18pp，是 ITT 的 45 倍。

三个口径列在一起：

| 口径 | 转化率提升 | 能不能用 |
|---|---|---|
| ITT | +59.4% | 能用，RCT 保证无偏 |
| Wald CACE | +1549.7% | 只能解释，不能决策 |
| 直接比曝光组 | +2675.8% | 有偏，不能用 |

CACE 我特意没拿来决策。它要求排他性，即随机分配只能通过曝光影响结果。但被分到投放组这件事本身可能就改变用户行为（广告位占位、频控差异），排他性站不住。

## 主效应

两比例 z 检验，两个主指标做了 Bonferroni 校正（α=0.025）。访问率 +1.03pp，转化率 +0.115pp，置信区间都很窄。

![三层指标](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/02_funnel.png)

顺手算了 MDE。按 α=0.025，访问率基线 3.82% 能测到 1.18% 的相对变化，转化率基线 0.19% 只能测到 5.47%；按设计口径 α=0.05，是 1.07% 和 4.97%。同一个实验，两个指标的灵敏度差五倍，这是后面建议改分流比例的直接原因。

链路这里我搞错过一次。一开始以为链路是「曝光 → 访问 → 转化」逐层嵌套，算 `visit/exposure` 得到 134.7%，超过 100%。查了才明白，访问可以在没有广告曝光的条件下自然发生，曝光和访问是部分重叠，不是父子。`exposure` 应该当成处理依从性指标，不是访问的前置漏斗。这个错如果没发现，后面所有漏斗分析都是错的。

## 按 f0 分层

五个箱的效应符号 100% 一致，全是正的。但增量极不均匀：

| 分箱 | 转化率（对照 → 投放） | 增量 | 占全部增量 |
|---|---|---|---|
| 1 | 0.147% → 0.188% | 975 单 | 7.5% |
| 2 | 0.590% → 0.988% | 9,553 单 | 73.2% |
| 3 | 0.158% → 0.239% | 1,916 单 | 14.7% |
| 4 | 0.061% → 0.078% | 397 单 | 3.0% |
| 5 | 0.036% → 0.045% | 207 单 | 1.6% |

第 2 箱一个箱子吃掉七成增量，五箱合计 13,048 单。这个合计是层占比加权口径，粗口径是 13,687，差 4.7%，不是加总没加对。前者是 `Σ s_k(c_tk − c_ck)` 的总体加权估计，后者是全体直接算差，两者的差正是上面说的分组-特征混杂。

![分层](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/03_strata.png)

异质性做了交互项联合 LR 检验，样本是确定性 fold 0（md5 分折，约 280 万行）：LR=16.04，df=4，p=0.0030。这个检验换过三次口径，值得记一笔。最早用 reservoir 抽样，同一 seed 两次运行 p 在 0.019~0.079 之间漂移，显不显著全凭运气；中间一次固定跑出 0.0723 判了不显著；换成确定性抽样、样本扩到 280 万之后，p=0.0030 才稳定下来。统计结论的可信度首先取决于能不能复现，其次才是 p 值。

## CATE：排序能用，绝对量不能用

T-learner，两臂各拟合一个 logistic，取预测概率之差。评估用五折轮转交叉拟合：md5 把 1,398 万行确定性分成 5 折（每折约 280 万），fold i 训练、fold i+1 评估，每个用户被且只被评估一次。

归一化 Qini 0.806，五折分别是 0.764 / 0.814 / 0.794 / 0.826 / 0.842，极差 0.078。同折自评 0.850，和交叉拟合差 0.045，过拟合缺口不大。极差那 8 个点里有一部分是协议造成的：`fold i 训练 → fold i+1 评估` 每折只用 1/5 数据训练，标准 cross-fitting 用 4/5，方差自然高一些。

![Qini](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/04_qini.png)

分位看，前 10% 的实际增量 +0.81pp（模型预测 +0.77pp，比值 1.04），是粗 ITT 的 7 倍，累计吃掉 85.7% 的增量；前 20% 到 91.8%。第 2 到第 9 分位预测普遍偏高，实际/预测落在 0.32~0.89 之间。排序可信，中后段的绝对量别直接用。

早期版本这个模型结论反复横跳，样本外 Qini 一会儿 0.05 一会儿 0.50。根因不在模型在抽样：reservoir 抽 60 万再对半切，训练集只有 30 万，方差大到结论随机。换成确定性五折后，任何机器任一次重跑，上面这些数字逐位一致。

另外跑了置换检验（在固定评估折上把 score 打乱 100 次），观测值远超 null 的 95% 分位。100 次重排的最小经验 p 是 1/101≈0.0099，所以只能写 p<0.01。置换只能证明比随机排序好，泛化要看交叉拟合那一组。

## 85.7% 里，大部分是曝光堆出来的

CATE 只喂了 f0–f11，没用 `exposure`。但如果模型排出来的顺序恰好和「谁会被曝光」高度同向，那 85.7% 就不能读成「说服力集中」。

按同一套样本外分位回算曝光：前 10% 的曝光率 17.61%，全体只有 3.06%，5.75 倍；top 10% 独占全部曝光的 57.5%。

![曝光诊断](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/05_exposure.png)

把各分位曝光率拉平，top 10% 的增量占比会从 85.7% 掉到 23% 左右。也就是说，这 85.7% 里大约七成是曝光分配堆出来的，剩下两成多才是真实的说服力差异。折算到每个曝光用户，top 10% 是 3.90%，第 11–80% 是 0.62%~1.24%，确实也更高，但没有 5.75 倍那么夸张。末两段 2.23% / 3.92% 对应的被曝光用户只有几千人，不能当证据。

这个诊断把定向结论的读法改了：定向 top 10%，很大程度上是在给一批本来就会看到广告的人再加一道标签。

这里假设每个曝光用户的效果在重新分配曝光时不衰减，是线性外推。如果边际递减，top 10% 的占比会更高，结论方向不变。

## 钱怎么算

增量转化 13,687 单（粗口径），单均毛利按 AOV 200 × 毛利率 30% = 60 元算，增量毛利 821,239 元。数据里没有曝光次数，也没有单次曝光成本，绝对 CPM 和 ROI 推不出来。能推的是反过来的那个数：盈亏平衡时，每个被曝光用户最多能花 1.92 元。

![成本上限](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/06_cost_per_user.png)

换成调整口径会低一些：f0 分层 13,048 单，毛利 782,895，上限 1.83 元；分位等权 11,217 单，毛利 673,040，上限 1.57 元。三套口径下 1 元都赚钱、2 元都亏，方向不变，但对外报钱的时候要说清用的是哪套。粗口径和分位口径差 18%，这个差距不是小数。

如果硬按「每个曝光用户只产生一次曝光、CPM 40 元」去算，会得到成本 17,128 元、ROI 47.95。这组数只能当假设演示，不能对外讲。

## 稳定性

五个体检口径，都不算强，列出来是为了让人看清结论的边界。

Bootstrap 400 次，在 150 万确定性子样本上跑：点估计 0.001227，比主 ITT 高 6.5%；标准误 0.000102，是解析 SE 的 3 倍。这是子样本的稳定性，不是主结果的置信区间。人群符号一致率 100%；对半切两半效应差 15.5%；每曝光用户成本 1.0 元时毛利率要 >15.64%，2.0 元时要 >31.29%。

第五个是提前看数的风险。模拟 500 次无效应场景（每次 20,000 单元，不是全量），如果按「每天看数、显著就停」，假阳性率会从 5% 涨到 25.4%，膨胀五倍。要么固定样本量，要么上序贯检验。

## 我算错过的几处

**以为该收缩投放，算完发现是亏的。**

前 10% 贡献 85.7% 的增量，直觉上应该只投这批人。算成本账就不是这么回事：

| | 增量毛利 | 成本（示意） | 净收益 |
|---|---|---|---|
| 全量投放 | 821,239 | 17,128 | 804,110 |
| 只投 top 20% | 753,662 | 3,426 | 750,236 |
| 只投 top 10% | 703,928 | 1,713 | 702,215 |

top 20% 比全量少赚 53,874 元（−6.7%），top 10% 少赚 101,895 元（−12.7%），净收益还是正的，只是更差。原因很简单：示意成本只占增量毛利的 2.1%，省 80% 的成本只省 1.37 万，丢掉 8.2% 的增量却是 6.76 万。省成本在当前成本结构下没有意义。

推了个临界条件：`(1−k)·c > (1−s)`，即 `c > (1−s)/(1−k) = 0.082/0.8 = 10.3%` 时定向才划算。现在是 2.1%，差五倍。这个阈值比笼统说「要精细化运营」有用，它告诉你什么时候该做、什么时候不该做。

早期版本这里写成了 `0.118/0.682 = 17.3%`，分母误用了 top20 的贡献占比 s，应该是 `1−k`。阈值高估 2.5pp，会把一部分本该定向的场景误判成「先提曝光率」。

**以为 50:50 是统计最优。**

做分流比例推演时发现，处理组方差 0.0031 大于对照组 0.0019，按 Neyman 分配，最优比例是 56:44，不是 1:1。再叠加抑制成本，成本最优点落在 40% 对照组。

![分流比例](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/07_design.png)

但这条曲线很平，30%、40%、50% 的总成本只差 5% 上下，别把 40% 当成精确答案。顺手还验证了一件事：分层随机化在这个指标上基本白做，`conversion` 只降 0.84% 方差，`visit` 降 1.44%。因为 `p(1−p) ≈ p` 且 `Σw_k·p_k ≡ p`，层间差异再大也换不来多少方差缩减；只有 p 落在 10%~50% 区间时分层才有实际收益，我们的 p=0.19% 正好在最没用的地方。

## 下一步

上面所有结论指向同一件事：**该提高曝光率，不是收缩人群**。

曝光率 3.60%，96.4% 的投放用户没曝光。但数据里没有曝光次数和成本，不能把这句话读成「预算打空」：原因可能是竞价、库存或频控，得下一轮实验去查。而且 85.7% 的集中度主要来自曝光分配，所以真正该问的不是「该投谁」，是「为什么 96.4% 的人拿不到曝光」。

具体方案在 [`03_下一步实验.md`](03_下一步实验.md)：先补埋点（7 张表，`user_id`、曝光成本、GMV、负反馈、pre-period），5% 流量 canary 看护栏，主实验 MDE 10%、60:40、总样本 1,751,450（对照 700,580 / 实验 1,050,870），约 7.5 天。成功了再测已曝光人群加频次的边际效应。

如果重做这个实验，分流改成 60:40，同样样本量下有效样本量能高 88.2%，转化率 MDE 从 5.47% 降到 4.25%（按 α=0.025；按设计口径 α=0.05 是 4.97%→3.86%）。只改分流比例这一个决策。推算过程在 [`02_设计推演.md`](02_设计推演.md)。

## 局限

数据没有 `user_id`，但每行本来就是不同用户，同一实验内按行独立的假设基本成立；没法验证的只是跨实验会不会有同一用户重复参与。没有 `timestamp`，做不了逐日曲线，稳定性只能用五个非时序口径替代。

特征全是匿名的（`f0`–`f11`），分层变量是数据驱动切出来的，映射不到「新客/老客」这种业务标签。落地的时候要重新定义人群。

CATE 后 80% 的校准很差，定向建议必须再过一轮实验验证，不能直接上线。top 10% 那 85.7% 里约七成来自曝光分配，这部分不能当成可复制的定向收益。

实验设计本身是数据集自带的（85:15 的分流、抑制组怎么设），这部分不是我做的。「设计 → 执行 → 读数」三步里，执行是别人做的，我只做了读数和事后推演。所以设计能力只能靠 `02_设计推演.md` 那份推演来证明，不是真跑过一轮。

SQL 那边和 Python 做了交叉对账，两臂样本量、visit 率、转化率六个指标完全一致（差异小于 1e-9）。CATE 那边 `cate_check.py` 独立重算 fold3→fold4 的 Qini，和 `analysis.py` 的对应折逐位一致，两条独立代码路径算出同样的数。
