# 广告投放的增量效应分析

Criteo 公开的 uplift 数据集，1,398 万**用户**，随机分成投放组和抑制组。

> **数据单元要说清楚**：每一行是一个 user，不是一次曝光。`exposure` 是「该用户是否至少被曝光过一次」的 0/1 标志，不是曝光次数。这个区别影响后续所有口径——比如「被曝光用户数 428,212」不能当成「428,212 次曝光」，因此绝对 CPM 成本推不出来（详见收益验证一节）。

我从头到尾跑了一遍：数据校验、主效应、依从性归因、分层、CATE、收益测算、稳定性检查，
代码和图表都在这个仓库里。做完分析又补了一轮「如果重做该怎么设计」的推演。

---

## 结论

广告有增量。转化率从 0.194% 到 0.309%，相对提升 59%，p < 1e-16，显著性这块没什么可争的。访问率从 3.82% 到 4.85%，涨了 27%。

但这个 59% 不能直接对外说。Criteo 在数据集说明里写了，「原始增量水平无法从数据还原」，因为他们做过非均匀子采样。所以量级不可信，能站住的只有方向和结构。

更值得说的是另一件事：**96.4% 的投放对象根本没看到广告**。

而且有个反常识的现象。被分到投放组、但因为频控没拿到曝光的那批人，访问率是 3.49%，比对照组的 3.82% 还低。同样没看到广告，分到投放组反而更差，说明曝光分配本身就不是随机的。

这意味着直接比「曝光组 vs 对照组」会严重高估效果。直接比的话转化率差 5.18pp，但真实的 ITT 只有 0.115pp，差了 45 倍。

## 数据

Criteo AI Lab 的 AdKDD'18 数据集，CC BY-NC-SA 4.0。

1,398 万行，16 列。`f0`–`f11` 是匿名化特征，`treatment` 是随机分组，`visit` 和 `conversion` 是两个结果标签，`exposure` 表示该用户是否至少被曝光过一次（user 级 0/1，不是曝光次数）。

分组是 15% 对照、85% 投放。不是 50:50，所以做 SRM 检查要按 85:15 检验，按 50:50 会误判成分流失败。

数据不进仓库，297 MB 超了 GitHub 单文件限制。克隆后先跑：


## 分析过程

### 先查数据能不能用

SRM 卡方 0.0000，p=0.999，分流和设计完全吻合。

协变量平衡检查（早期版本叫 AA 检验，名字不对）看了 12 个特征，最大标准化均值差 0.0488，全在 0.1 以下，两组分布平衡。

标签自洽性也查了：`conversion=1` 但 `visit=0` 的行是 0，对照组出现 `exposure=1` 的行也是 0。数据干净。

### 主效应

两比例 z 检验，两个主指标做了 Bonferroni 校正（α=0.025）。

访问率 +1.03pp（+27.07%），转化率 +0.115pp（+59.45%），置信区间都很窄。

顺手算了 MDE。访问率基线 3.82%，这个样本量能测到 1.07% 的相对变化；转化率基线只有 0.19%，同样样本量只能测到 4.97%。所以两个指标要分开看，一个看灵敏度，一个看商业价值。

![三层指标](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/02_funnel.png)

### 链路这里我搞错了一次

一开始我以为链路是「曝光 → 访问 → 转化」逐层嵌套的。算 `visit/exposure` 的时候发现是 134.7%，超过 100%。

查了一下才明白，访问可以在没有广告曝光的条件下自然发生。曝光和访问是部分重叠的关系，不是父子。`exposure` 应该当成处理依从性指标，而不是访问的前置漏斗层。

这个错误如果没发现，后面所有漏斗分析都是错的。

### 依从性

`P(exposure | treatment) = 3.60%`。分到投放组的 1,188 万人里，只有 42.8 万真的看到了广告。

三个口径算下来差别很大：

| 口径 | 转化率提升 | 能不能用 |
|---|---|---|
| ITT | +59.4% | 能用，RCT 保证无偏 |
| Wald CACE | +1649.7% | 只能解释，不能决策 |
| 直接比曝光组 | +2675.8% | 有偏，不能用 |

CACE 我特意没拿来用。它要求排他性，即随机分配只能通过曝光影响结果。但这个场景下，被分到投放组本身可能就改变了用户行为（广告位占位、频控差异），排他性站不住。所以它只是参考，决策还是用 ITT。

![依从性](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/01_compliance.png)

### 分层

按 `f0` 五分位切，5 个箱子的效应符号 100% 一致，都是正的。但增量非常集中：

| 分箱 | 转化率（对照 → 投放） | 增量贡献 |
|---|---|---|
| 1 | 0.147% → 0.188% | 975 单（7.5%） |
| 2 | 0.590% → 0.988% | 9,553 单（73.2%） |
| 3 | 0.158% → 0.239% | 1,916 单（14.7%） |
| 4 | 0.061% → 0.078% | 397 单（3.0%） |
| 5 | 0.036% → 0.045% | 207 单（1.6%） |

第 2 箱一个箱子吃掉 73% 的增量，合计 13,048 单。

异质性交互项联合 LR 检验 p=0.0799，未过 5% 水平，**未见显著异质性**（早期版本写 0.0187，那是另一次不可复现抽样下的跑数）。不过增量贡献差 49 倍，业务上的差异比这个 p 值看起来大得多。

![分层](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/03_strata.png)

### CATE 模型

T-learner，两臂各拟合一个 logistic，取预测概率之差。Qini（归一化 = 2×面积−1） 0.0465（样本外）。

光看这个数会以为模型很好。但我做了分位校准，看每个分位的「实际增量 / 预测增量」：

前 10% 是 1.23，前 20% 是 0.97，校准不错。但 30% 之后掉到 0.25–0.76，模型系统性高估。

所以只有头部可信。后面那 80% 的证据撑不起「砍掉 80% 投放量」这种决策。

另外跑了随机重排的 null 分布，100 次打乱 score，Qini 均值 -0.008，95% 分位 0.109，观测值远超。**注意：100 次重排的最小经验 p 是 1/101 ≈ 0.0099，所以只能写 `p < 0.01`，不能写 p=0.000**。重排只能证明「比随机排序好」，不能证明泛化——泛化要看样本外那一组（见上）。

![Qini](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/04_qini.png)

### 收益

增量转化 13,687 单。**数据没有曝光次数**（exposure 是用户级 0/1），无法算绝对 CPM 成本。

增量 CPA 是 1.25 元/单。单均毛利如果按 200 元客单 × 30% 算，是 60 元。

绝对 ROI 无法从数据推导（没有曝光次数），绝对值只能当口径演示。

所以对外报的是：**每个被曝光用户的成本上限 1.92 元**。这是反向推导——不依赖「总曝光次数」这个拿不到的数据。超过就亏，低于就有余量。

![CPM 敏感性](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/05_cpm.png)

### 稳定性

五个体检口径。Bootstrap 400 次，标准误对应的变异系数 9.9%；人群符号一致率 100%；随机对半切两半效应差 16.7%；决策结论在毛利率 >0.63% 时不翻转。

第五个是提前看数风险。模拟了 500 次无效应场景（**toy simulation，每次 20,000 单元，不是 1,398 万全量**），如果按「每天看数显著就停」，假阳性率会从 5% 涨到 25.4%，膨胀 5 倍。所以要么固定样本量，要么上序贯检验。

## 几个我算错过的地方

写这一节是因为改了几次判断，过程比结论有意思。

**以为该收缩投放，算完发现是亏的。**

CATE 在 train/test 分割后，**样本外 Qini 只有 0.0465**（接近随机），前 10% 人群样本外只贡献 33.7% 的增量——没有可复现的人群集中度。样本内 Qini 高达 1.04、前 10% 累计 101.2%（超过 100%，业务上不可能），这是过拟合的铁证。**「只投 top 10%」这条策略没有证据支持。**

| | 增量毛利 | 成本 | 净收益 |
|---|---|---|---|
| 全量投放 | 821,220 | —（缺曝光次数）| — |
| 只投 top 20% | 724,332 | 3,426 | 720,907 |

净亏 83,203 元，10.3%。

原因很简单：成本只占增量毛利的 2.1%。省 80% 的成本只省 1.37 万，丢 11.8% 的增量是 9.85 万。省成本这件事在当前成本结构下毫无意义。

推了个临界条件：`(1−k)·c > (1−s)`，即 `c > (1−s)/(1−k) = 0.118/0.8 = 14.75%` 时定向才划算。现在是 2.1%，差 7 倍。

> 早期版本这里写成了 `0.118/0.682 = 17.3%`——分母误用了 top20 的贡献占比 s，应该是 `1−k`。阈值高估 2.5pp，会把一部分本该定向的场景误判成「先提曝光率」。

**以为 50:50 是统计最优。**

做分流比例推演的时候，发现处理组方差 0.0031 大于对照组 0.0019，按 Neyman 分配，最优比例是 56:44，不是 1:1。

再叠加成本因素，最优点在 40% 对照组。但这几个比例的总成本只差 5%，曲线很平，别把 40% 当精确答案。

![分流比例](https://gcore.jsdelivr.net/gh/223456png/ad-lift-experiment@main/report/figures/06_design.png)

**以为分层随机化能降方差。**

用真实分层结构算了一遍，`conversion` 只降 0.84%，`visit` 降 1.44%，基本白做。

代数上看是必然的：`p(1-p) ≈ p`（p 很小时），而 `Σw_k·p_k ≡ p`，两式一凑，分层方差就等于随机方差。分层只是把同一个数换个算法，没引入新信息。

只有 p 在 10%–50% 区间、层间差异大的时候，分层才有实际收益。我们这个指标 p=0.19%，正好在最没用的地方。

## 下一步该做什么

上面所有结论都指向同一件事：**该提高曝光率，不是收缩人群**。

曝光率只有 3.60%，96.4% 的投放打空了。把曝光率提到 5%，保守估计转化能涨 4.5%，成本端因缺少曝光次数数据无法核验，此策略需要下一轮实验补齐曝光成本埋点后再验证。

具体方案在 [`03_下一步实验.md`](03_下一步实验.md)：先补埋点（7 张表，补 user_id、曝光成本、GMV、负反馈、pre-period 数据），canary 5% 流量看护栏，主实验 MDE 10%、848,763/臂、全量跑 7.3 天，成功了再测已曝光人群加频次的边际效应。

顺带说一句，如果重做这个实验，分流改成 60:40，有效样本量能高 88.2%，转化率的 MDE 从 4.97% 降到 3.86%。只改分流比例这一个决策。推算过程在 [`02_设计推演.md`](02_设计推演.md)。

## 局限

数据的硬约束：没有 `user_id`，标准误是按行独立算的，可能偏小；没有 `timestamp`，做不了逐日曲线，稳定性只能用非时序的五个口径替代。

特征都是匿名的（`f0`–`f11`），所以分层变量是数据驱动切出来的，没法映射成「新客/老客」这种业务标签。落地的时候要重新定义人群。

CATE 后 80% 校准差，定向建议必须再过一轮实验验证，不能直接上线。

实验设计本身是数据集自带的（85:15 的分流、抑制组怎么设），这部分不是我做的。完整的闭环「设计 → 执行 → 读数」我只走了后两步，设计能力是靠后面的推演补的，见 `02_设计推演.md`。
